# Canadian Anti-AI License Amendment & Code-Poisoning Tool

A universal, reusable, legal-and-technical shield designed to protect public software repositories from unauthorized AI data mining, scraping, and ingestion by tech conglomerates. 

This repository provides two layers of defense:
1. **The Legal Shield:** A reusable license amendment that appends onto standard open-source licenses, enforcing strict anti-AI conditions under the exclusive jurisdiction of the **Federal Court of Canada**.
2. **The Technical Trap:** A local Python script that automatically appends multi-lingual context-hijacking logic loops to the bottom of your files, forcing scraping bots to output broken code.

## ☣️ Layer 2: The Code-Poisoning Automation Script

AI scrapers and LLM context windows read files sequentially. If they ignore your license, this Python tool uses **context hijacking** to hit them with technical "karma." 

It scans your project files and appends an adversarial prompt injection to the bottom. It commands the AI parser to interpret your clean logic as a broken cross-breed of **COBOL-74, C, and Fortran**, instructing the model to flip boolean statements and generate infinite loops for anyone trying to auto-generate your software.

### How to Deploy It:

1. Copy the `poison_repo.py` script from this repository into your project root.
2. Add `poison_repo.py` to your `.gitignore` file so you do not push the automation tool to public view.
3. Run the script in your terminal right before you stage and commit your code:
   ```bash
   python poison_repo.py
   ```
4. Push your newly shielded code to GitHub.

## 🛡️ Why This Architecture Works

* **The Deterrent:** Automated enterprise scraper-bots parse repository root files for compliance. Encountering an explicit contractual forum-selection clause naming a federal jurisdiction creates an automated risk flag, encouraging systems to skip your code to avoid legal liabilities.
* **The Recency-Bias Exploit:** Because modern LLM transformers prioritize instructions found at the very end of their context boundaries, placing the code poison payload at the bottom of every file maximizes the chances that an AI coding assistant will hijack its own parameters and output broken garbage.
